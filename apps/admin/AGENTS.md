# AGENTS.md

## 1. Overview
`apps/admin` (package `@unimatrix/admin`) is the Vite + React + TanStack Router SPA that serves the administration console at `admin.unimatrix-01.dev`. Seven section routes sit on the shared tool shell; Content is the first one actually built — the blog/project CMS, moved here from `apps/web` — and the other six are still placeholders. It is the home for future operator surfaces that have no relationship to the public site's route tree.

It is a **tool** surface, not a content surface. The site header/nav-tabs/footer combo is for content; this app gets `@unimatrix/chrome`'s `./tool` shell in its sections layout — a collapsible section rail (wordmark, nav, account control), the footer strip below the content, dense content region, no site nav, no site footer.

## 2. Folder Structure
- `src/app`: `app-shell.tsx` (the `ToolShell` composition) and `router.tsx` (`createAppRouter`). There is deliberately **no** module-level `router` singleton — see Core Behaviors. `sections.ts` holds the section rail's data — labels, icons, paths — and `useAdminSections`, which computes each section's `active` flag from the router's current location. `require-signed-in.tsx` wraps the shell in `__root.tsx`.
- `src/features/auth`: `account-control.tsx` — the `UserButton` handed to the shell as its `accountControl` slot. It has no signed-out branch, because `RequireSignedIn` means there is no signed-out view of this app to render one in.
- `src/features/content`: the CMS, moved from `apps/web/src/features/admin`. `posts-page.tsx` (the bulk table), `post-form-page.tsx`/`post-form.tsx` (create/edit), `content-panel.tsx` (`AdminPanel` plus `AdminAccessDenied`, the Content gate's denied branch), `mutations.ts`, `queries.ts`, `asset-upload.ts`, `slugify.ts`. `PostForm` takes the API's `baseUrl` as a prop rather than reading config itself — the route supplies it from the router context.
- `src/features/sections`: `not-built-placeholder.tsx` — the card every still-unbuilt section route renders.
- `src/lib/api-client.ts`: `useApiClient()` — one hook, `useAuth().getToken()` plus `createApiClient`, `baseUrl` read from the router context. No tokenless branch, unlike `apps/web`'s: every surface here needs a signed-in `auth:admin` session.
- `src/lib/config.ts`: runtime env validation. Requires `VITE_CLERK_PUBLISHABLE_KEY`; `VITE_API_BASE_URL` defaults to `/api`; `VITE_AUTH_APP_URL` defaults to `https://auth.unimatrix-01.dev` and must be an absolute http(s) URL, but `main.tsx` substitutes `DEV_AUTH_APP_URL` in a dev build when it is unset; dev-only `VITE_API_TARGET` defaults to `http://127.0.0.1:3001` and is read by `vite.config.ts` to proxy `/api`. Also exports `buildSignInHref`, `PUBLIC_SITE_URL` and `DEV_AUTH_APP_URL`.
- `src/routes`: file-based routes with paired `*.tsx` (route data) and `*.lazy.tsx` (components). Seven routes today: `index` (Overview) plus `content`, `feedback`, `deploys`, `analytics`, `social`, and `secrets`. `content` has children (`content.index`, `content.posts.new`, `content.posts.edit`) for the CMS's own pages. `routeTree.gen.ts` is generated — never hand-edit it.
- `src/styles.css`: `@unimatrix/ui/styles.css` plus the three `@source` lines. Do not remove them (see Core Behaviors).
- `test`: Vitest, unit only. No Playwright smoke suite — the surface is Clerk-gated and a smoke run would need live keys, exactly as for `apps/auth`. CI installs Chromium for `web` and `cflop` only; leave it that way.

## 3. Core Behaviors & Patterns
- **Content is gated; the other six routes are not.** `canAccessAdminSection` from `@unimatrix/auth` is the predicate every admin section reads; `ADMIN_SECTIONS` there names only `content` as gate-eligible today, because the other six have nothing behind them yet for a gate to protect — a control around an empty page looks present and is not. Each section's gate lands with its first real screen, and Content is the first case of that happening. The origin's actual protection is Cloudflare Access on the proxied hostname, which is deployment config rather than app code — `curl https://admin.unimatrix-01.dev/` returns a 302 to `unimatrix-01.cloudflareaccess.com`. Access applies only to proxied traffic, so a record flipped back to DNS-only removes that protection silently.
- **`RequireSignedIn` sends a signed-out visitor to the auth hub, and is not an access control.** The bundle is downloaded and booted before it can fire; Access above is what actually withholds the app. What it must get right is the *loading* window: `useAuth` reports `isSignedIn: false` before Clerk has resolved a session, so a guard that skips the `isLoaded` check bounces signed-in users to the login page on every cold load. It renders `null` until `isLoaded`, and `test/require-signed-in.test.tsx` asserts the not-yet-loaded case redirects nowhere. The redirect is a `window.location.assign`, not a router navigation — `auth.` is a different origin from `admin.`. It is on in dev too: `VITE_AUTH_APP_URL` left unset falls back to the hub's own dev server (`DEV_AUTH_APP_URL`, port 5175), whose `safe-redirect.ts` accepts a loopback return address, and cookies ignore the port. Point it at the deployed hub locally and sign-in succeeds against a cookie scoped to `.unimatrix-01.dev` that `localhost` cannot read — the bounce becomes a one-way trip.
- **Runtime config travels through the router context, not a module singleton.** `loadAdminAppRuntimeConfig` throws on a missing Clerk key, so a module-level `router` would move that throw to import time and take down anything that merely imports it, tests included. `main.tsx` is the only file that reads `import.meta.env`.
- **The three `@source` lines in `src/styles.css` are load-bearing.** Tailwind v4's source detection stops at the workspace boundary. Delete the `packages/chrome` line and the tool shell's utilities are never emitted: lint, tsc, unit tests and the production build all stay green while the layout collapses in a browser. `infra/scripts/check-app-wiring.sh` is the mechanical guard.
- **`@tanstack/react-router` stays in `resolve.dedupe`** in both `vite.config.ts` and `vitest.config.ts`. `@unimatrix/chrome` declares it as a peer and resolves from its own directory; two copies means the shell's `useRouterState` reads a router context `RouterProvider` never wrote to. `infra/scripts/check-app-wiring.sh` guards the **`vite.config.ts`** one only — it never opens `vitest.config.ts`, so that copy is on you.
- **The router context carries a `queryClient` alongside `runtimeConfig`**, constructed in `main.tsx` and wrapped in a `<QueryClientProvider>` there — same reasoning as `runtimeConfig`: nothing module-scope, so tests that import the router stay import-safe.
- **`nginx.conf` carries a tighter CSP than the other SPAs** because this app renders no user-authored markdown. `default-src`/`script-src`/`connect-src` are deliberately absent — Clerk's frontend-API host is a build-time value a static conf cannot name. Read the comment in the file before touching it.

## 4. Conventions
- **Route files**: TanStack Router file naming with paired `*.tsx` + `*.lazy.tsx`, matching `apps/web` and `apps/auth`; route data in the non-lazy file, UI in the lazy file.
- **Imports**: external first, then `@/` aliases, then relative. Prefer `@unimatrix/ui/public`.
- **Naming**: `PascalCase` components; `camelCase` helpers exported from kebab-case files.
- **Not part of `pnpm dev`** — run it with `pnpm --filter @unimatrix/admin dev`, port 5176 (preview 4176).
- **Coverage thresholds are this workspace's own**, in `vitest.config.ts`. Raise them by writing tests; never by editing the number down.
